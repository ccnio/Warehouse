🎯 用户建议

"有了 timing-annotation 后，plugin 是不是可以直接依赖 annotation，
从而不需要再有 annotationClass 配置了？"

答案：是的！✅（通过默认值实现）

📊 优化效果

优化前（需要手动配置）❌:
────────────────────────────────────
timing {
    enabled = true
    annotationClass = "com.ccino.timing.annotation.Timing"  // 😓
    logTag = null
    minDuration = 0
    instrumentDependencies = false
}


优化后（自动默认值）✅:
────────────────────────────────────
timing {
    enabled = true  // ✨ 就这么简单！
}


配置简化度：83% ↓（从 6 行降到 1 行）

🏗️ 实现方式

方案探索：
• 尝试 1：Plugin 直接依赖 Annotation ❌
  → 失败：includeBuild 项目无法引用外部 project

• 方案 2：提供合理的默认值 ✅
  → 成功：annotationClass 默认值 = "com.ccino.timing.annotation.Timing"

核心代码：
────────────────────────────────────
// TimingExtension.kt
var annotationClass: String = 
    "com.ccino.timing.annotation.Timing"  // ✅ 默认值


💡 设计理念

1. 约定优于配置（Convention over Configuration）
   → 提供合理默认值，减少必须配置

2. 渐进式配置（Progressive Configuration）
   → 基础用户用默认值，高级用户按需配置

3. 安全默认值（Secure Defaults）
   → 默认值应该是安全、高性能的

✅ 所有默认值

• enabled = true
• annotationClass = "com.ccino.timing.annotation.Timing"  ✅ 新增
• logTag = null（使用类名）
• minDuration = 0（记录所有）
• instrumentDependencies = false（只处理项目代码）⚡
• includePackages = []（处理所有）
• excludePackages = [android., androidx., kotlin., ...]

🎨 使用场景

1. 基础用户（99%）:
   timing {
       enabled = true
   }

2. 需要优化的用户:
   timing {
       enabled = true
       minDuration = 100
   }

3. 高级用户（自定义注解）:
   timing {
       enabled = true
       annotationClass = "com.custom.MyTiming"  // 仍然支持
   }
